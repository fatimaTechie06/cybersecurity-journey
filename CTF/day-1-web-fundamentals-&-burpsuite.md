# Day 1: Web Fundamentals & Burp Suite

Today I started learning **web security fundamentals and Burp Suite** as part of my cybersecurity and CTF journey.

## Web Fundamentals

### HTTP Requests and Responses
Learned the basic request-response cycle between a client and a web server.

```text
Client (Browser)
      ↓
 HTTP Request
      ↓
 Web Server
      ↓
 HTTP Response
      ↓
Client (Browser)
```

### HTTP Methods
Learned about common HTTP methods:

- `GET` - Retrieve a resource
- `POST` - Send data to the server
- `PUT` - Update a resource
- `DELETE` - Delete a resource

### HTTP Status Codes
Learned the purpose of HTTP response status codes, including:

- `200 OK` - Request successful
- `301/302` - Redirection
- `400 Bad Request` - Invalid request
- `401 Unauthorized` - Authentication required
- `403 Forbidden` - Access denied
- `404 Not Found` - Resource not found
- `500 Internal Server Error` - Server-side error

### Cookies
Learned that cookies are small pieces of data stored by the browser and sent with requests to help websites maintain state and user information.

### Sessions
Learned how sessions allow a web application to maintain a user's state across multiple requests, commonly using a session identifier stored in a cookie.

### Authentication
Learned that authentication is the process of verifying **who a user is**, such as through a username and password.

### Authorization
Learned that authorization determines **what an authenticated user is allowed to access or perform**.

# Burp Suite

## Proxy
Learned how Burp Suite acts as an intermediary between the browser and the web server.

```text
Firefox
   ↓
Burp Suite Proxy
   ↓
Web Server
```

Used Burp Proxy to intercept and inspect HTTP traffic from Firefox.

## CA Certificate
Installed the Burp Suite CA certificate in Firefox to allow Burp to inspect HTTPS traffic.

## Firefox Integration
Configured Firefox to send its web traffic through Burp Suite.

Verified that Firefox requests were successfully intercepted by Burp.

## HTTP History
Used **Proxy → HTTP history** to view requests generated by Firefox.

Observed requests containing:

- HTTP methods
- URLs
- Headers
- Cookies
- Request paths

## Request Inspection
Inspected real HTTP requests and learned how to identify important parts such as:

```http
GET / HTTP/2
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

## Repeater
Learned how to send a captured request to **Repeater** for manual testing.

Repeater allows a request to be modified and sent repeatedly without performing the action again in the browser.

## Request Modification
Performed my first request modification by changing:

```http
GET / HTTP/2
```

to:

```http
GET /robots.txt HTTP/2
```

## Response Analysis
Analyzed the server's response after modifying the request.

The server returned:

```http
HTTP/2 404 Not Found
```

This demonstrated how changing the requested resource can change the server's response.

# Key Learning

The basic Burp Suite workflow I practiced today was:

```text
Firefox
   ↓
Burp Proxy
   ↓
Intercept HTTP Request
   ↓
HTTP History
   ↓
Inspect Request
   ↓
Send to Repeater
   ↓
Modify Request
   ↓
Send Request
   ↓
Analyze Response
```

## Day 1 Takeaway

Today I built the foundation for web application security testing by learning how HTTP works and how Burp Suite can be used to inspect and modify web traffic.

I also successfully configured **Firefox with Burp Suite**, intercepted real HTTP traffic, used **HTTP History**, and performed my first request modification using **Repeater**.
